# SDK generation with stlc

Hypeman's Go and TypeScript SDKs are generated by
`.github/workflows/stlc-generate.yml` from `openapi.yaml` and `stainless.yaml`.

## Flow

1. A config-repo PR generates `stlc/preview/pr-<number>` branches in the two
   internal SDK staging repositories and posts one build-manifest comment.
2. Merging the config PR validates the integrated SDKs and pushes staging
   `main` only after bootstrap, lint, tests, and clean-worktree checks pass.
3. A maintainer manually runs `Promote SDKs` in each staging repo. The workflow
   fast-forwards public production `main` and refuses divergent histories.
4. Release-please opens the version and changelog PR in production. Merging it
   publishes the package.
5. The scheduled sync fast-forwards production commits back into staging.

## Normal API changes

Update `openapi.yaml` and `stainless.yaml`, then open a PR. Review the generated
preview branches and manifest diagnostics before merging. Publishing still
requires a manual promotion and a release-please PR merge.

## Integration test

Run the real generator from any branch without touching staging or production
`main`:

```bash
gh workflow run stlc-generate.yml --ref <branch> -f integration_test=true
```

The run creates a unique `stlc/integration-test/run-<run-id>` branch and draft
PR in both staging repos. Never merge these PRs; close them and delete their
branches after review.

## Custom code and recovery

Edit custom code in `stainless/sdks/<target>/`, then seal and commit it from the
config repo:

```bash
cd stainless
stlc build --commit "feat: describe the change" --push
cd ..
git add stainless/custom-code
git commit -m "chore(stlc): seal custom code"
git push
```

Run the `stlc` recovery commands from the workspace (`cd stainless` from the
repo root).

- `stlc status` reports the required next command.
- Use `stlc build --continue` after resolving an integration conflict.
- Use `stlc build --abort` to return to the last good state.
- `stlc diagnostics` shows diagnostics from the latest build.
- `stlc repair` recovers broken custom-code tracking.
- Never force-push staging or production `main`.

CI installs the private `stlc` packages at the exact revisions pinned in
`.github/actions/setup-stlc/action.yml`. Upgrade those revisions together and
rerun full SDK validation.

## Final hosted cutover

Remove hosted-only secrets and uninstall the Stainless GitHub App only after a
complete preview → staging → promotion → release-please → publish → back-sync
round trip succeeds for both SDKs.
